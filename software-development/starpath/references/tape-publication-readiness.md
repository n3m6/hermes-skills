# Tape publication (O-5) readiness

Obligation: prove the exact canonical compressed tape bytes committed by the epoch relation are covered by native venue commitments whose consensus roots are authenticated on Arbitrum — Celestia primary, Ethereum blobs the fallback. A nonempty opaque inclusion field or a self-claimed data root never closes it. Two layers are both required: pure exact-inclusion validation (in `packages/challenge-evidence`, no I/O) and anchor validation against finalized L2 state (infrastructure port + challenge-facing adapter).

## Inputs that must exist before any live arm can run

- Sealed C1 work corpus + work manifest + private work configuration, four cases in fixed order: `empty`, `ordinary`, `incompressible`, `maximum`. `maximum` is `params::da::TAPE_MAX_PRINTS` prints, i.e. 1,048,576 prints = 2,097,152 sealed Stream V2 frames; `ordinary`/`incompressible` are one 128th of that.
- Generated by `prepare-tape-validation-work <private-config> <new-public-output-directory>`. Private config keys: `market_hex`, `reference_id`, `maker_account_hex`, `taker_account_hex`, `token_hex`, `reference_authority_key_path`, then per case name `<case>_genesis_manifest_path`, `<case>_recipient_key_bundle_path`, `<case>_state_path`, `<case>_seal_key_path`. Existing state paths or output directories are a failure, not an overwrite.
- Four case genesis manifests at **distinct initial deployment epochs**. Bootstrap the local tee-node binary once per case with a distinct initial epoch sequence / chain id / settlement address.
- Eight owner-only credential files (single value, no trailing newline): Celestia RPC URL, Celestia auth token, Blobstream proof URL, Arbitrum RPC URL, L1 RPC URL, L1 beacon URL, deployer private key, publisher private key.
- Ethereum arm additionally needs a secret-free versioned transport config plus a runtime config containing `l1_execution_endpoint`, `beacon_endpoint`, `l2_execution_endpoint`, `publisher_private_key_path`, and a nonzero `writer_id_hex`; `legacy_sidecar_endpoint` is required only in the legacy-sidecar retrieval mode and forbidden in BeaconBlob mode.
- The fallback drill profile also carries the two archive endpoints and two 32-byte archive seeds (an explicit development/validation-only archive composition; production retention durability is a separate obligation).

## Celestia endpoint requirements — "we have an RPC URL" is not enough

- The adapter submits through the Celestia node JSON-RPC with a bearer JWT, one namespace-v0 blob per segment: the node's blob, share, and header APIs must be enabled.
- The **node's own keyring account pays**, so that account needs testnet TIA. Funding the arm's EVM keys does not fund Celestia submission.
- The namespace must be 29 bytes, version 0, non-reserved, and **not** the historical fixture namespace that `packages/params` still exports for the old testnet slice — the production deployment profile rejects that value outright.
- The 7 MiB per-envelope ceiling and the 900-second finalized-Blobstream deadline are params/ADR-owned. Confirm the ceiling on the pinned network before booking and record the measurement; a contradicting measurement stops the gate, it does not get rounded away.

## External unknowns to verify before spending anything else

- Is the SP1 Blobstream oracle actually deployed on the target testnet? The arm pins both a proxy address and an implementation address plus their runtime code hashes; if there is no oracle, the Celestia arm cannot authenticate a single anchor and the drill cannot run as specified — that is a scope decision, not a prep task.
- Where does the Blobstream **tuple proof** service live? The arm speaks a Starpath-specific tuple-JSON wire, not the stock Blobstream API, and that service is not in this repo.
- The canonical Inbox address for the L2 testnet, and the predicted publisher/anchor addresses produced by the deterministic deployment manifest (validated against the real deployment before any dependent transaction is sent).

## Fault and restart boundaries the drill must exercise

Withhold the finalized Blobstream proof so the primary cannot lock; restart at the durable boundaries (`pending-celestia`, `ethereum-selected`, `late-identical-celestia`); cover the deadline boundary cases just before, at, and just after the params-owned deadline; treat a conflicting submission as terminal, and allow no venue switch after the relation-ready freeze. Evidence is written only after exact late-primary reconciliation, so no partial `passed` result may ever be emitted.

## Harness modes (one entry point)

- Local deterministic: empty / ordinary / incompressible, a `--local-maximum` mode for the maximum-print codec, segmentation, and blob-geometry path, plus dedicated pure-verifier lib tests.
- Live arms: per-venue modes, both together, and three measurement modes (7 MiB Celestia envelope, Blobstream readiness, eight-blob Ethereum segment).
- Fallback drill, and a `--soak` mode that only records that the multi-day gate is not automated.
- A local run proves codec/geometry coverage only; a live arm proves publication and finalized-anchor evidence for the pinned configuration. Neither is a soak, and neither discharges the obligation.
